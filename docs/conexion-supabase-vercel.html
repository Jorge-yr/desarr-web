Conexión de Supabase con Vercel

Desarr · Procedimiento interno · Proyecto desarr-web · Octubre 2026

El sitio lee Supabase solo en el servidor. No hace falta instalar la integración de Supabase dentro de Vercel. Esa integración crea otras variables y puede pisar las que ya usa el login.

Dónde sacar cada dato en Supabase

Proyecto: Clinex_DB. Referencia: egiupfunbffmitgzvhme.

  1. Abrir el proyecto en Supabase.
  2. Ir a Project Settings → API Keys → pestaña Legacy anon, service_role API keys.
  3. Copiar la clave marcada anon y public. Empieza con eyJ. Esa es la que va en Vercel.
  4. No copiar la clave service_role. Esa salta la seguridad por fila y no se carga en el sitio.
  5. La URL del proyecto no es la de Data API. No usar la que termina en /rest/v1/. La URL correcta es: 
    https://egiupfunbffmitgzvhme.supabase.co

Qué cargar en Vercel

Proyecto desarr-web → Settings → Environment Variables. Entorno: Production. Tipo: Secret.

  • SUPABASE_URL = https://egiupfunbffmitgzvhme.supabase.co
  • SUPABASE_ANON_KEY = la clave anon public

Los nombres van sin el prefijo NEXT_PUBLIC_. El login corre en el servidor y no necesita publicar esas variables en el navegador. El código también acepta los nombres con prefijo si ya existieran.

Después de guardar

  1. Redeploy del último deployment de Production, rama master.
  2. Esperar a que el estado quede Ready.
  3. Probar https://www.desarr.com/login con un usuario que exista en Authentication y tenga fila en admin_usuarios.

Cambiar una variable no alcanza: el deploy que ya está publicado sigue con el valor anterior hasta el redeploy.

Si el login dice que el correo o la clave están mal

  • Revisar que SUPABASE_URL no tenga /rest/v1/ al final.
  • Revisar que la clave sea la anon, no la service_role.
  • Revisar que el usuario esté en el mismo proyecto Clinex_DB y que Confirmed at tenga fecha.
  • Crear el usuario desde Authentication → Add user, con Auto Confirm User. No depender del correo de reseteo si el navegador muestra error de proxy.
