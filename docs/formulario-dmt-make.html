Formulario DMT y conexión a Make

Desarr · Procedimiento interno · Octubre 2026

DMT es el Diagnóstico de Madurez Tecnológica. En el sitio se llama también DET. La persona responde 7 preguntas, ve su nivel y, al confirmar, el sitio envía un solo registro.

Dónde está el formulario

  • Página pública: https://www.desarr.com/auditoria-tecnologica
  • Pantalla: src/components/DET.tsx
  • Preguntas y puntajes: src/lib/det-data.ts
  • Recepción: POST https://www.desarr.com/api/det-submit

El formulario no llama a Make mientras la persona escribe. El único envío es al aceptar el resultado, para que Make reciba un registro completo: respuestas, recomendaciones y si quiere que lo contacte un asesor.

Qué hace el sitio al confirmar

  1. Valida nombre, empresa, correo, teléfono, país, provincia, tipos de empresa, las 7 respuestas, el puntaje y el nivel.
  2. Intenta agregar una fila en Google Sheets, hoja DET, columnas A a Z. El rango se puede cambiar con GOOGLE_SHEETS_DET_RANGE.
  3. Envía el mismo diagnóstico en JSON al webhook de Make, variable MAKE_WEBHOOK_URL.

Alcanza con que uno de los dos destinos responda bien. Si Sheets y Make fallan, el sitio avisa al administrador por correo y la persona ve un error.

Conectar Make

  1. En Make, crear un escenario nuevo.
  2. El primer módulo es Webhooks → Custom webhook. Crear un webhook y copiar la URL. Empieza con https://hook. y pertenece a Make.
  3. Dejar el escenario en ON. Si está apagado, el sitio recibe error y no guarda el lead por ese camino.
  4. En Vercel, proyecto desarr-web → Settings → Environment Variables → Production, cargar: 
    MAKE_WEBHOOK_URL = la URL del webhook
    Tipo Secret. No usar la variable del registro de socios: el DMT lee solo MAKE_WEBHOOK_URL. El registro usa MAKE_REGISTRO_WEBHOOK_URL y, si esa no existe, cae en la misma MAKE_WEBHOOK_URL.
  5. Redeploy de Production en la rama master. Sin redeploy, el sitio sigue sin la URL nueva.
  6. Completar el diagnóstico en /auditoria-tecnologica hasta aceptar el resultado. En Make tiene que aparecer una ejecución con el JSON.

Qué llega a Make

El cuerpo es JSON. Los campos que el escenario puede mapear son:

  • type: siempre det
  • timestamp
  • lead: fullName, company, email, phone, country, state, companyTypes
  • diagnostic.totalScore y diagnostic.maturityLevel
  • recommendations
  • solicitaAsesor: SÍ o NO
  • answersFlat: q1_registros a q7_escalamiento, con el texto de la opción elegida

Prueba automática

GitHub Actions corre npm run test:dmt-smoke los lunes y jueves a las 09:00 ART, y también se puede disparar a mano. Postea a https://www.desarr.com/api/det-submit con el correo prueba_automatica@dmt.com. Si falla, manda un correo usando RESEND_API_KEY y ADMIN_NOTIFY_EMAIL.

Si no llega a Make

  • El escenario está apagado o el webhook se regeneró y la URL de Vercel quedó vieja.
  • No se hizo redeploy después de guardar MAKE_WEBHOOK_URL.
  • La variable está solo en Preview y el formulario público usa Production.
  • El correo de alerta [Desarr] Falló envío a Make (det) trae el estado HTTP que respondió Make.
